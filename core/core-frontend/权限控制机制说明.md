# DataEase 前端权限控制机制说明

## 📋 概述

DataEase 采用了**多层权限控制体系**，从页面访问到数据访问都有完整的权限控制机制。权限控制主要分为以下几个层级：

1. **路由权限** - 控制用户可以访问哪些页面
2. **菜单权限** - 控制用户可以看到哪些菜单项
3. **按钮权限** - 控制用户可以执行哪些操作
4. **数据权限** - 控制用户可以看到哪些数据（行权限、列权限）

## 1. 路由权限控制

### 1.1 路由守卫机制

**文件位置**: `src/permission.ts`

路由权限通过 Vue Router 的**前置守卫（beforeEach）**实现：

```typescript
// 路由前置守卫
router.beforeEach(async (to, from, next) => {
  // 1. 启动进度条
  start()

  // 2. 检查登录状态
  if (!userStore.getToken) {
    // 未登录，跳转到登录页
    if (whiteList.includes(to.path)) {
      next() // 白名单路径直接放行
    } else {
      next('/login') // 其他路径跳转到登录
    }
    return
  }

  // 3. 已登录，检查路由权限
  if (!permissionStore.getIsAddRouters) {
    // 动态加载用户可访问的路由
    await permissionStore.generateRoutes()
  }

  // 4. 验证用户是否有权限访问目标路径
  if (pathValid(to.path)) {
    next() // 有权限，放行
  } else {
    next('/401') // 无权限，跳转到无权限页面
  }
})
```

### 1.2 白名单机制

某些页面无需登录即可访问（如登录页、分享链接页）：

```typescript
const whiteList = ['/login', '/de-link', '/chart-view', '/admin-login', '/401']
```

### 1.3 动态路由加载

**文件位置**: `src/store/modules/permission.ts`

根据后端返回的路由配置动态生成路由：

```typescript
actions: {
  // 生成路由
  generateRoutes(routers?: AppCustomRouteRecordRaw[]) {
    return new Promise<void>(resolve => {
      // 根据后端返回的路由配置生成前端路由
      const routerMap = generateRoutesFn2(routers)

      // 添加 404 兜底路由
      this.addRouters = routerMap.concat([{
        path: '/:catchAll(.*)',
        component: NotFoundPage
      }])

      // 合并静态路由和动态路由
      this.routers = cloneDeep(routes).concat(routerMap)
      resolve()
    })
  }
}
```

### 1.4 路径权限验证

```typescript
// 验证路径是否有效
export const pathValid = (path) => {
  const permissionStore = usePermissionStore()
  const routers = permissionStore.getRouters

  // 递归检查用户是否有权限访问该路径
  return hasCurrentRouter(locations, routers, 0)
}
```

## 4. 数据权限控制

数据权限是 DataEase 权限体系中最核心的部分，包括**行权限**和**列权限**。

### 4.1 行权限（Row Permissions）

行权限控制用户可以看到数据表中的哪些行（记录）。

#### 相关 API

**文件位置**: `src/api/dataset.ts`

```typescript
/**
 * 查询行权限列表
 * @param page 页码
 * @param limit 每页数量
 * @param datasetId 数据集 ID
 */
export const rowPermissionList = (page, limit, datasetId) =>
  request.get({
    url: `/dataset/rowPermissions/pager/${datasetId}/${page}/${limit}`
  })

/**
 * 查询行权限目标对象列表
 * @param datasetId 数据集 ID
 * @param type 类型（user/role/org/dept）
 */
export const rowPermissionTargetObjList = (datasetId, type) =>
  request.get({
    url: `/dataset/rowPermissions/authObjs/${datasetId}/${type}`
  })

/**
 * 保存行权限
 * @param data 权限数据
 */
export const saveRowPermission = (data) => {
  return request.post({ url: '/dataset/rowPermissions/save', data })
}

/**
 * 删除行权限
 */
export const deleteRowPermission = (data) => {
  return request.post({ url: '/dataset/rowPermissions/delete', data })
}
```

#### 行权限配置示例

```json
{
  "datasetId": 123,
  "permissionType": "row",
  "whiteListType": "user", // user/role/org/dept
  "whiteListUsers": ["user_001", "user_002"],
  "rowPermissions": [
    {
      "field": "region",
      "operator": "eq",
      "value": "北京"
    },
    {
      "field": "amount",
      "operator": "lt",
      "value": "10000"
    }
  ]
}
```

**说明**:
- 用户只能看到 `region = '北京'` 且 `amount < 10000` 的数据行

## 5. 权限控制流程

### 5.1 用户登录流程

```
1. 用户输入用户名密码
   ↓
2. 后端验证，返回 Token
   ↓
3. 前端保存 Token 到 Store 和缓存
   ↓
4. 获取用户基本信息和角色信息
   ↓
5. 获取用户的菜单权限和路由权限
   ↓
6. 动态生成可访问的路由
   ↓
7. 跳转到首页或第一个有权限的页面
```

### 5.2 页面访问权限验证流程

```
1. 用户访问某个页面
   ↓
2. 路由守卫触发
   ↓
3. 检查是否登录
   ↓ 未登录 → 跳转到登录页
   ↓ 已登录
   ↓
4. 检查是否在白名单
   ↓ 是 → 直接放行
   ↓ 否
   ↓
5. 检查是否有路由权限
   ↓ 否 → 跳转到 401 页面
   ↓ 是
   ↓
6. 放行，进入页面
```

### 5.3 数据访问权限验证流程

```
1. 用户查看数据集/图表
   ↓
2. 前端携带 Token 请求后端 API
   ↓
3. 后端验证 Token 有效性
   ↓
4. 后端查询用户的数据权限配置
   ├─ 行权限：过滤数据行
   └─ 列权限：过滤数据列
   ↓
5. 返回用户有权限查看的数据
   ↓
6. 前端渲染数据
```

## 6. 权限配置示例

### 6.1 配置数据集行权限

```typescript
// 1. 查询现有的行权限
const permissions = await rowPermissionList(1, 10, datasetId)

// 2. 添加新的行权限
await saveRowPermission({
  datasetId: datasetId,
  whiteListType: 'user', // 对用户生效
  whiteListUsers: ['user_001', 'user_002'],
  rowPermissions: [
    {
      field: 'department',
      operator: 'eq',
      value: '销售部'
    }
  ]
})

// 3. 查询目标对象（用户列表）
const users = await rowPermissionTargetObjList(datasetId, 'user')
```

### 6.2 配置数据集列权限

```typescript
// 保存列权限
await saveColumnPermission({
  datasetId: datasetId,
  whiteListType: 'role', // 对角色生效
  whiteListRoles: ['role_viewer'],
  columnPermissions: [
    'id',
    'name',
    'department'
    // 不包含敏感字段
  ]
})
```

### 6.3 配置菜单权限

```typescript
// 1. 查询菜单资源树
const menuTree = await menuTreeApi()

// 2. 查询菜单权限

  menuId: 'dataset',
```

## 7. 权限相关 Store

### 7.1 User Store (`src/store/modules/user.ts`)

存储用户信息、Token、角色等：

```typescript
export const useUserStore = defineStore('user', {
  state: () => ({
    token: '',           // 登录 Token
    userInfo: null,      // 用户信息
    roles: [],          // 角色列表
    permissions: []     // 权限列表
  }),

  actions: {
    // 设置 Token
    setToken(token) {
      this.token = token
      setToken(token)
    },

    // 获取用户信息
    async getInfo() {
      const res = await getUserInfo()
      this.userInfo = res.data
      this.roles = res.data.roles
      return res
    }
  }
})
```

### 7.2 Permission Store (`src/store/modules/permission.ts`)

管理路由权限：

```typescript
export const usePermissionStore = defineStore('permission', {
  state: () => ({
    routers: [],        // 所有路由
    addRouters: [],     // 动态添加的路由
    isAddRouters: false // 是否已添加路由
  }),

  actions: {
    // 生成路由
    async generateRoutes(routers) {
      const routerMap = generateRoutesFn2(routers)
      this.addRouters = routerMap
      this.routers = cloneDeep(routes).concat(routerMap)
    }
  }
})
```

## 8. 前端权限检查指令

虽然代码中没有提供自定义指令，但通常可以通过以下方式实现：

```typescript
// 示例：权限检查指令（如需要可添加）
import { useUserStore } from '@/store/modules/user'

const vPermission = {
  mounted(el, binding) {
    const { value } = binding
    const userStore = useUserStore()

    if (value && !userStore.permissions.includes(value)) {
      // 没有权限，移除元素
      el.parentNode?.removeChild(el)
    }
  }
}

// 使用示例
// <el-button v-permission="'user:delete'">删除</el-button>
```

## 9. 权限控制最佳实践

### 9.1 前端权限检查

```typescript
// 在组件中检查权限
import { usePermissionStore } from '@/store/modules/permission'

const permissionStore = usePermissionStore()

// 检查是否有某个路由的权限
const hasPermission = permissionStore.getRouters.some(
  route => route.path === '/dataset'
)

// 根据权限显示/隐藏按钮
<el-button v-if="hasPermission">操作</el-button>
```

### 9.2 后端权限验证

**重要**：前端权限控制只是为了用户体验，真正的权限验证必须在后端进行！

- 前端：隐藏无权限的菜单和按钮
- 后端：验证每个 API 请求的权限

### 9.3 Token 管理

```typescript
// Token 存储在多个地方
// 1. Pinia Store（响应式）
// 2. localStorage/webStorage（持久化）

// 使用示例
import { useCache } from '@/hooks/web/useCache'

const { wsCache } = useCache()

// 设置 Token
wsCache.set('app.token', token)

// 获取 Token
const token = wsCache.get('app.token')

// 清除 Token（退出登录）
wsCache.delete('app.token')
```

## 11. 总结

DataEase 的权限控制体系具有以下特点：

1. **多层防护**：路由 → 菜单 → 按钮 → 数据
2. **前后端结合**：前端控制显示，后端验证权限
3. **灵活配置**：支持用户、角色、组织、部门多维度权限
4. **细粒度控制**：支持行级和列级数据权限
5. **动态加载**：根据用户权限动态生成可访问的路由和菜单

**注意事项**：
- ⚠️ 前端权限控制仅用于用户体验，不能作为安全防线
- ⚠️ 所有敏感操作必须在后端进行权限验证
- ⚠️ Token 过期需要重新登录获取新 Token
- ⚠️ 权限变更后可能需要重新登录才能生效
